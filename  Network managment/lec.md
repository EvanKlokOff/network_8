# SNMP (Simple Network Managment Protocol)

* Вендорно независимый протокол
* Мониторинг сети, работа с клиентским либо сетевым оборудованием

* Диспетчер SNMP может получить доступ к агенту с помощью get, set. 
  * get - запрос параметров
  * set - установка параметров

* trap - запрос с информацией от агента к диспетчеру

* Для настройки необходимо специальное ПО для компов/серверов
  * На управляемых устройствах должны быть размещены SNMP агенты, которые хранят инфу об устройствах в локальной бд MIB
  * Получив запрос от диспетчера, агент смотрит в MIB, чтобы прислать ему ответ
  
* Сететевое оборудование поддерживает SNMP из коробки

## Версии SNMP

Строка сообщества это пароль, задаваемый на диспетчере и агенте. Строки сообщества не шифруются и передаются в открытом виде

SNMPv2с - включает не только код ошибки, но ещё и тип

SNMPv3 - может обеспечить целостность сообщений, шифрование, аутентификацию. Уровни настраиваемые, в зависимости от задачи и по

## Про строки сообщества

Используются в SNMPv1 SNMPv2

* рекомендуется использовать строки сообщества только для чтения, т.к они передаются по сети в открытом виде, и чтобы никто не подглядел и не натворил делов

## Идентификатор переменных MIB

Переменные в MIB позволяют осуществлять наблюдение за сетевым оборудованием и управление им

переменные в MIB - это идентификаторы объектов, за которыми происходит управление и наблюдение

Для любого устройства дерево идентификатора включает несколько ветвей, которые могут совпадать для разных типов устройств. Ответвление происходит, когда появляется уникальность от вендора устройства

Переменные могут быть определены в RFC

Идентифицировать объект можно словами, которые определены в RFC, либо цифровым кодом(как в cisco)

# SPAN (Switched Port ANalyzer)

* технология для зеркалирования трафика в коммутаторах циско
* Технология Cisco

Для анализа трафика используют утилиты по типу WireShark, которые позволяют анализировать трафик проходящий через устройство. К сожалению невсегда есть доступ к устройству, поэтому придумали **зеркалирование портов**

* Трафик можно также дублировать на системы Обнаружения/предотвращения вторжений

Зеркалирование заключается в том, что при особой настройке свитча, указанный трафик будет дублироваться на указанный порт (см картинку)

Зеркалирование не меняет направление трафика и не как не мешает его прохождению, но порт на который дублируется трафик перестаёт быть участником сети(через этот порт больше не происходит коммуникация)

## RSPAN (Remote Span)
SPAN работает только с одним коммутатором, что оч плохо масштабируется. Для этого придумали RSPAN, который создаёт магистраль с анализирующим устройством, которое напрямую не подключено к коммутатору, который хотим исследовать

Для зеркалированного VLAN лучше настроить отдельную выделенную VLAN, которая будет VLAN RSPAN

# IP SLA (IP Service Level Agreement)

Позволяет мониторить сеть, анализировать производительность сети

Позволяет проверять доступность настроенных устройств

На устройстве может быть запущено несколько IP SLA. Можно осущетвлять проверки локально на усйтростве, либо с помощью SNMP проверять данные

![alt text](image-22.png)

## Настройка IP SLA
