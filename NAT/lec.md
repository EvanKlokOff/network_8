# NAT (Network Address Translation)

Был придуман из-за дефецита ipv4 адресов, когда решили разделить пространство ip адресов на частные(серые) и публичные(белые) ip адреса

частные адреса могут переиспользоваться несколько раз в разных локальных сетях, т.к они не маршрутизируются

![alt text](image.png)

Необходим преобразователь, преобразующий серый адрес в белый

NAT настраивается на **граничном маршрутизируемом устройстве**

тупиковая сеть - подсеть или локальная сеть (LAN), подключенная к основной сети только через один маршрутизатор (шлюз), который обеспечивает единственный выход во внешнюю среду

Есть случаи, когда граничных устройств несколько, в таком случае придётся ввести специальные правила, чтобы не было коллизий внешних адресов

![alt text](image-1.png)

## Принцип работы NAT

![alt text](image-2.png)

Маршрутизатор получает пакет из внутренней сети, где в качестве источника указан серый ip адрес. Затем NAT выделяет и назначает белый ip и записывает у себя в nat таблице такое отображение(cерый -> в белый). Также NAT модифицирует пакет, подменяя в нем серый адрес источника на белый. Затем такой пакет отправляется в сеть

Когда к роутеру придёт ответ, то роутер выполнит обратное отображение с адресом назначения, найти серый ip адрес, подмненить его в пакете и отправит его в сеть

## Типы адресов NAT

* inside global address - внутренний глобальный адрес(адресс источника видимый из внешней/глобальной сети). Такой адрес маршрутизируется

* inside local address - внутренний локальный адресс(адресс источника видимый из внутренней части сети). Такой адрес не маршрутизируется

* outside global address - внешний глобальный адрес(адресс назначения видимый из глобальной сети). Такой адрес маршрутизируется

* outside local address - внешний локальный адрес(адресс назначения видимый из внутренней сети). Такой адрес не маршрутизируется

outside global address и outside local address - это адреса назначения, **часто могут быть одинаковыми** 

в нашем примере, т.к глобальный адресс сервера доступен из вне(адрес маршрутизируется), то nat не стал его подменять, поэтому они совпадают

Но бывают случаи, когда адрес сервера имеет свой локальный серый ip, тогда NAT придётся его тоже подменить(на примере такая ситуация не отражена). Посмотри DNAT

## Статический NAT

Есть статическое отображение серых ip в глобальное, оно не изменяется со временем

![alt text](image-5.png)

## Динамический NAT

Есть пул глобальных адресов. Отображение серых адресов в глобальные строится динамически, в зависимости от настроек пула и запросов устройств. Устройству по запросу выделяется какой-то свободный адрес из пула. Первое обратившееся устройство получает доступный глобальный адрес. Как только пул адресов закончится, то новым устройствам придётся ожидать, пока освободится какой-нить глобальный адрес

![alt text](image-6.png)

## PAT (перегрузка по портам)

Позволяет сделать несколько отображений серых адресов в один глобальный. Отличие таких отображений достигается с помощью выбора номера порта с транспортного уровня

## Динамический NAT

Есть выделенный пул внешних ip адресов.

Устройство делает однозначное соответствие, но глобальный адрес выбирается динамически из пула

Шаги по преобразованию ip адресов:
1. выполняется проверка, а можно ли такие ip адреса преобразовывать
2. Если проверка пройдена, то устройство заглядывает в nat таблицу и ищет там подходящее преобразование. Если нашел то использует его
3. Если найти преобразование не получилось, то устройство добавляет его в nat таблицу и переходит на шаг 2

Т.к адрес назначает динамически, то из внешней сети не получится обратиться к устройству из внутренней сети, т.к в момент обращения белый ip адрес может быть ещё не назначен для нужного компа 

По умолчанию преобразование станет неактивным после 24 часов, т.е после этого времени глобальный адрес снова можно распределить между внутренними ip. **Таймер можно настраивать**

При настройке пула, нужно обращать внимание на кол-во устройств из внутренней сети. Т.к если кол-во глобальных ip адресов будет меньше, то некоторые компы останутся без ip и им придётся ожидать освобождение ip адреса

## PAT(Port Access Translation)

Их существует 2 вида:
1) 1 выделенный глобальный адрес, с которым можно проводить преобразования адресов
2) несколько глобальных адресов, но их меньше чем внутренних адресов, т.к иначе бы использовали динамический NAT

В преобразовании участвуют номера портов с транспортного уровня + ip адреса

Преобразуем адреса в один внешний адрес с указанием номера порта(пытаемся сохранить номер порта источника при возможности, если этого сделать не получается делаем +1 к номеру порта, пока мы не найдем свободный порт)

Доступный номер порта будет искаться только в пределах своей группы портов. Если мы исчерпали порты, доступные в своей группе, то PAT с этим глобальным адресом невозможен, придётся выделять новый другой

## Преймущества и недостатки NAT

NAT Сохраняет схему ip адресов, т.к если бы его не было и использовались глобальные ip адреса, то со временем они могут измениться(динамические IP либо смена провайдера) и пришлось бы настраивать сеть заново. NAT спасает, т.к можно использовать уже готовую схему + перенастроить граничные роутеры для работы NAT

Повышение гибкости для подключения к внешней сети, т.к приходится манипулировать только частными адресами(не надо арендовывать и согласовывать белые ip адреса), а потом в случае необходимости доступа в публичную сеть  можно настроить nat на граничном роутере

Позволяет скрывать внутреннюю адресацию для компов из внешней сети

Протоколы не использующие транспортный уровень будет проблематично использовать с PAT

## NAT64

Используется когда необходимо передавать ipv6 пакеты в ipv4 сетях. Происходит трансляция ipv6 адресов в ipv4 адреса и обратно

Также можно использовать dualstack - работать на ipv6 и ipv4 одновременно

Также можно использовать туннелирование, где ipv6 пакеты будут вкладываться в ipv4 пакеты
