# Туннелирование(VPN)

Если кратко то мы стараемся инкапсулировать данные для транспортировки через WAN

Эмулируем частную сеть через интернет с помощью туннелирования

![alt text](image-9.png)

экономия за счёт того, что мы не строим частную физическую сеть, а используем уже готовую инфраструктуру + алгоритмы шифрования для обеспечения приватности

Очень просто подключить нового сотрудника, т.е хорошо масштабируется

Т.к передаётся поверх обычного интернета есть поддержка всех широкополосных супер пупер блейзинг технологий

![alt text](image-10.png)

Есть 2 вида vpn:
* site-to-site
* remote access

![alt text](image-12.png)



## Site-to-Site VPN

Пользователь даже не подозревает что данные передаются через туннель, всё происходит прозрачно

для этого на границах сети устанавливаются специальные роутеры, работающие как шлюзы vpn, между которыми настраивается постоянный туннель vpn

Пользовательский трафик внутри vpn не шифруется

![alt text](image-11.png)


## Remote access VPN

Передача трафика происходит непрозрачно, т.к пользователю нужно самому создавать vpn туннель. Так же такой туннель не будет постоянно работать

# GRE(Generic Routing Encapsulation)
Gre создаёт туннель поверх ip сети

Трафик участвующий при создании gre туннеля:
* инкапсулируемый протокол
  * Информация протокола, которого необходимо передать сквозь туннель
* инкапсулирующий протокол
  * Протокол создающий туннель
  * В нашем случае это gre
* транспортный протокол
  * Протокол на котором построена сеть, через которую будут пускать трафик
  * Для gre это ip
![alt text](image-15.png)

## Про GRE

При создании туннеля создаётся сеть точка-точка поверх любой конфигурации сети с любой топологией

GRE по умолчанию не использует шифрование

GRE не хранит инфу о состоянии, отсутствует механизмы по управлнею потоками - т.е он без установки соединения

GRE используется для создания site-to-site vpn

![alt text](image-17.png)

## GRE IPsec

т.к GRE не шифрует инфу, требуется использовать IPSec для защиты инфы. Поэтому используют IPsec туннели

IPsec туннелями используют вместе с GRE туннелями, чтобы маршрутизировать широковещательный или групповой трафик, т.к голый IPSec позволяет маршрутизировать только конкретные адреса

![alt text](image-18.png)

# Принципы создания IPSec туннелей

**Нужно убедиться что на 2ух взаимодействующих устройствах набор настроенных протоколов будет одинаковым**

![alt text](image-26.png)

Сам по себе ipsec не является протоколом, это скорее набор правил использования различных протоколов безопасности для обеспечения безопасной передачи данных

Можно создать кастомный набор различных правил, чтобы закрывать те или иные дырки в безопасности

## Инкапсуляция в IPsec

связка AH + ESP редко используется, т.к плохо работает с NAT

AH не шифрует данные, поэтому его используй, когда конфедициальность не требуется, но обеспечивает аутентификацию и целостность

ESP обеспечивает конфидициальность, аунтетификацию и целостность. Если выбираем ESP нужно также пикнуть технологию которыее тоже обеспечивают конфидициальность и аунтетификацию и целостность

## Настройка IPsec

Мы создаём политику для создания туннеля. ISAKMP - набор алгоритмов использующихся для создания тунелей

После создания политики выбираем какие алгоритмы там будут использоваться

Номер группы - это алгоритм диффи хелмана
